ข้อกำหนดสำหรับแก้ไขปัญหาจาก Builder Performance Monitor

1. แก้เฉพาะ Interaction และ Element ที่ผู้ใช้ส่งให้เท่านั้น
2. ห้ามทดสอบหรือแก้หลาย Element พร้อมกัน
3. ห้ามทดสอบ Element อื่นต่อเอง หลังแก้เสร็จให้หยุดเพื่อให้ผู้ใช้ทดสอบซ้ำ
4. ห้ามเพิ่ม ลบ หรือเปลี่ยนโครงสร้าง Element, Column, Split และ Section
5. ห้ามเปลี่ยนพฤติกรรมหรือหน้าตาของ Builder หากไม่ได้รับคำสั่ง
6. ห้าม Refactor ขนาดใหญ่หรือแก้ไฟล์ที่ไม่เกี่ยวข้องโดยไม่มีหลักฐาน
7. ห้ามเปลี่ยน Threshold เพื่อทำให้ผล Performance กลายเป็นสีเขียว
8. ห้ามปิด หลีกเลี่ยง หรือแก้ React Profiler เพื่อซ่อนปัญหา
9. ห้ามลบ Cache, Memoization หรือ Performance optimization โดยไม่มีหลักฐาน
10. ห้ามใช้ console log, Backend, localStorage หรือระบบจัดเก็บอื่นสำหรับผลการวัด
11. ห้ามเพิ่ม Dependency และห้ามใช้ Docker
12. ห้ามสรุปว่า Re-render มากกว่า 0 คือปัญหาเสมอ ต้องพิจารณาสาเหตุและต้นทุนจริง
13. ต้องวิเคราะห์สาเหตุจากค่าที่ส่งให้ก่อนแก้ไขโค้ด
14. ต้องรักษาความแม่นยำของ Builder Performance Monitor
15. ห้ามเปลี่ยน UI ของ Performance Monitor หากไม่ได้รับคำสั่ง
16. หลังแก้ให้ตรวจ Production build, lint และข้อผิดพลาดของไฟล์ที่แก้
17. ห้าม Commit หรือ Push Git หากผู้ใช้ไม่ได้สั่ง

Prompt สำหรับใช้งาน

แก้เฉพาะปัญหาจาก Interaction นี้เท่านั้น ห้ามแก้หรือทดสอบ Element อื่น
ห้ามเปลี่ยน UI พฤติกรรม โครงสร้าง Element หรือ Threshold ของ Builder Performance Monitor
ต้องวิเคราะห์หาสาเหตุก่อนแก้ และรักษาความแม่นยำของระบบวัด
ห้ามใช้ console log, Backend, localStorage, Dependency ใหม่ หรือ Docker
หลังแก้ให้ตรวจ Production build และ lint แล้วหยุด เพื่อให้ฉันทดสอบ Interaction เดิมซ้ำเอง


ตอนนี้ยังทดสอบและใช้งานต่อได้ แต่ควรทยอยแก้โดยจัดลำดับ:

no-undef และ Hook warnings
Error ในไฟล์ที่ใช้งานจริง
Fast Refresh
Unused code
ไม่ควรแก้ทั้งหมดอัตโนมัติในครั้งเดียว เพราะบางจุดอาจเปลี่ยนพฤติกรรมระบบครับ
